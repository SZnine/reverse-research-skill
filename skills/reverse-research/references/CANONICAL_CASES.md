# Canonical Control Cases

## Delegate a visual/device micro-action

The agent has produced a patched build. Determining whether a two-frame animation aligns correctly requires launching the app and looking at a physical device. Ask the user to install, open one screen, and report one of two visual outcomes. Do not build a vision/UI automation stack for this single decision.

## Do not delegate agent-cheap work

The workspace contains two manifests and the question is whether an exported flag changed. Diff the files directly. Asking the user to open both files would transfer work without reducing uncertainty or cost.

## Stop an unproductive loop

Two Frida attempts fail with the same class-not-found result and no new classloader evidence. Do not keep changing delays. Inspect process/classloader/module context or ask the user to perform the exact flow that loads the feature.

## Skip durable state

The user provides one decompiled method and asks what it appears to do. Explain it with a decompiler caveat. Do not initialize a project, toolbox profile, or evidence store.

## Use durable state

A migration spans static mapping, runtime probing, a repack, and a later device test. Initialize `reverse-state`; keep the active decision and next action compact, and checkpoint at meaningful stage boundaries.

## Cost as a tie-breaker

A parser branch can be resolved either by a ten-minute broad trace or by generating one controlled second sample. Prefer the sample when both can answer the same question. Do not spend a long reasoning pass assigning numeric utility scores.
